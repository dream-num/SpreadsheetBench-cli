# 30-524-31

## 结论

该题失败是 output 在 7 个未匹配行写入了字符串 `#N/A`，而 golden 在正式 `data_only=True` 口径下这些单元格值为 `None`。`answer_position` 是 `'Exp-DB'!E1:E53`，复现 mismatch 为 `E7,E8,E28,E29,E30,E45,E46`。

agent 把 `E1:E53` 全部替换为静态分类值，并对找不到 key 的行写 `#N/A`。golden 对这些行保留 `VLOOKUP(...)` 公式；openpyxl 读取缓存值时为空，因此评测判 FAIL。

## 证据与复现

- prompt: `.runs/univer-agent/codex-gpt-5-5-verified400-all-20260526-231834/524-31/task/prompt.md`
- output: `.runs/univer-agent/codex-gpt-5-5-verified400-all-20260526-231834/524-31/task/outputs/case_1/output.xlsx`
- golden: `data/spreadsheetbench_verified_400/spreadsheet/524-31/1_524-31_golden.xlsx`
- eval: `test_case_results: [0]`

正式口径差异：

| 单元格 | output | golden data_only |
| --- | --- | --- |
| E7 | `#N/A` | `None` |
| E8 | `#N/A` | `None` |
| E28 | `#N/A` | `None` |
| E29 | `#N/A` | `None` |
| E30 | `#N/A` | `None` |
| E45 | `#N/A` | `None` |
| E46 | `#N/A` | `None` |

公式文本也不同：output 这些单元格是静态字符串，golden 是 `=VLOOKUP(Dx & "*",$A$1:$B$37,2,0)`。

## 解题过程分析

agent 先加载 skill，读 workbook 和 `E1:E3` cell model。之后写 `categorize_case_1.js`：读取 `A1:B37` 作为 key/category，读取 `D1:D53` 描述，先尝试 `startsWith`，再尝试 `includes`，匹配不到则返回 `#N/A`，并把结果作为静态字符串写入 `E1:E53`。`verify_case_1.js` 检查了若干行，并确认 `E1:E53` no longer contains formulas。最后正常导出 output。

stdout 的验证重点是部分映射正确，以及“无公式”。这和 golden 保留公式的形态相反。

## 卡点分析

- 题意理解偏差：用户要“自动 assign categories”，原表已有公式框架；agent 选择静态值替换，且把未匹配行实体化为 `#N/A`。
- 验证不足：只验证典型成功映射和“无公式”，没有按评测的 `data_only=True` 值比较未匹配行。
- 过程耗时 353 秒，接近上限但未超时；无 CLI 导出错误。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。
- univer-cli skill 指引不清：次要因素。skill 强调公式/值类型验证，但没有帮助 agent 判断这类已有公式任务应保留公式还是静态化。

## 建议

遇到已有公式列时，优先延续公式语义并验证未匹配行的缓存值。不要把 Excel 错误值字符串化，除非题目明确要求显示文本 `#N/A`。
