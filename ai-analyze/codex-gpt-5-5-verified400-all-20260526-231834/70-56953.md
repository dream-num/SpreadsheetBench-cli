# 70-56953

## 结论

该题 FAIL 是动态抽取区域结构处理错，另有浮点缓存精度差异。按 `data_only=True` 比较 `Sheet2!I2:L9`，output 与 golden 17/32 个单元格一致，15 个不同。

主要问题是源数据有两个 70kW 分组：低速组 A2:D6 和高速组 A7:D9。golden 在输出中保留第二个分组的 header 到 `I7:L7`，再放两行数据到 `I8:L9`；agent 只按 `A3:A15=F2` 过滤数据行，跳过了 `A7:D7` header，导致 `I7:L9` 整体错位。

## 证据与复现

- prompt：输入 Power(kW)=F2，显示对应 predefined ranges；`answer_position='Sheet2'!I2:L9`。
- 差异样本：
  - `I7:L7` output `70,700,1428,468.137...`，golden `Power (kW), Engine HS, Power take-off (rpm), (Nm)`。
  - `J8/K8/L8` output 第二条高速数据，golden 第一条高速数据。
  - `I9:L9` output 空，golden 第二条高速数据。
- 浮点差异：`L3:L6` 仅精度不同，如 `450.1683501683502` vs `450.16835016835`，按当前评测精确比较仍算 FAIL。
- agent 公式只索引 `$A$3:$D$15` 中 A 列等于 F2 的行；header 行 `A7="Power (kW)"` 不可能被匹配。
- 范围外检查：源列 D 的公式缓存因导出重算出现尾数差异，不是主动写入污染。

## 解题过程分析

agent inspect `Sheet2!A1:L15`，用 `univer run --code` 读取 values/formulas/cellDatas/backgrounds，然后写 `/task/work/case_1_write.js`：

- 清空 `I2:L9`。
- `I2:L2` 写 `=$A$2:$D$2` header 公式。
- `I3:L9` 写 `INDEX/AGGREGATE` 公式，抽取 `A3:D15` 中 A 列等于 F2 的第 n 个匹配行。
- 导出后又 run 读取 `I2:L9` cellDatas。

验证没有检查分组 header 是否需要复制，也没有对照 orange sample 的分段结构。

## 卡点分析

- 结构理解错误：把两个 predefined ranges 当成单一连续数据表过滤，忽略中间 header 行。
- 公式范围硬编码：`A3:D15` 加 `A=F2` 无法表达“匹配 power 的整段 range，包括分段 header”。
- 浮点缓存风险：公式重算造成 `L` 列尾数与 golden 精确值不同，当前评测无容差。
- 验证不足：只确认公式和值存在，未核对 I7:L9 的行语义。

## 归因分析

归因分类：agent 自身题意理解/推理/验证问题；runner/评测流程问题。

不判断为 CLI bug：主要错位来自 agent 公式逻辑。浮点尾数差异暴露评测精确比较的脆弱性，但即使忽略尾数，I7:L9 结构仍失败。

## 建议

- 先识别每个 power block 的 header/data 边界，再输出完整 matching block，而不是只筛 A 列等于 F2 的行。
- 对公式导出导致的浮点缓存尾数差异，后续可考虑在评测或输出策略中使用静态 golden precision 值；但本题首要修复是分组结构。
