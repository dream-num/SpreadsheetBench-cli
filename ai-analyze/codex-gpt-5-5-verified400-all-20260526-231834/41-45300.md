# 41-45300

## 结论

该题失败是 agent 删除了 `FT` 前面的尾随空格。`answer_position` 是 `B1:B4`。golden 公式 `=LEFT(Ax,FIND("FT",Ax)-1)` 会保留 `FT` 前的空格；agent 用 `trimEnd()` 去掉了该空格。正式评测逐值比较字符串，4 个目标单元格全部 FAIL。

## 解题过程分析

agent 写了 `case_1_truncate_ft.js`，读取 `A1:A4` 的 cell model，找到 `text.indexOf("FT")`，然后 `text.slice(0, ftIndex).trimEnd()` 写入 `B1:B4`。`case_1_verify.js` 回读 `B1:B4` 的 `v/t/f`，确认是文本值且没有公式。导出正常，耗时 78 秒。

关键问题在 `trimEnd()`。题干说“remove everything starting with FT while keeping preceding text intact”，golden 的 Excel 公式严格保留了 preceding text，包括 `FT` 前的空格。

## 卡点分析

- 过度规范化：agent 按清理文本的习惯去掉尾随空格，但正式评测按精确字符串比较。
- 验证不足：只确认文本模型，没有用长度或可见占位检查尾随空格。
- 公式/样式差异不影响评测；值差异是唯一失败原因。

## 归因分析

- agent 自身题意理解/验证问题：主要原因。
- skill 指引副作用：prompt 中通用 normalize 建议提醒了 trim，但这里不应 blindly trim；agent 没有遵守“不要盲目 trim 需要保留原文”的限制。

## 建议

字符串截断题应默认保留截断点之前的原始字符。验证时用 `repr`、长度或末尾字符检查，不要只看显示文本。
