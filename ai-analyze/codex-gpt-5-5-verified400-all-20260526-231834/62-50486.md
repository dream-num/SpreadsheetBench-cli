# 62-50486

## 结论

该题 FAIL 是输出文本大小写不匹配。按 `data_only=True` 比较 `A2:A5`，4/4 个单元格不同：output 为 `Chep/Chep/Loscam/Loscam`，golden 为 `CHEP/CHEP/LOSCAM/LOSCAM`。

agent 识别了哪一列有数值，但没有保留表头中的大写文本。

## 证据与复现

- prompt：根据两列中哪列含数字，在 A 列显示 `Chep` 或 `Loscam`；`answer_position=A2:A5`。
- workbook 表头：`C1=CHEP`、`D1=LOSCAM`。
- output：`A2:A5 = Chep, Chep, Loscam, Loscam`。
- golden：`A2:A5 = CHEP, CHEP, LOSCAM, LOSCAM`。
- golden 公式形态：`=IFNA(INDEX($C$1:$D$1,MATCH(99^99,$C2:$D2)),"")`，直接返回表头文本。
- 范围外检查：无 answer_position 外值/公式变更。

## 解题过程分析

agent inspect `A1:D5`，写 `/task/work/case_1_edit.js`，读取 `C2:D5` 的 cell data，用数字判断 CHEP/LOSCAM 列，然后写显式文本 `{v:"Chep"}` 或 `{v:"Loscam"}` 到 `A2:A5`。之后再次 inspect 并导出。

它没有把 `C1:D1` 表头作为输出源，也没有对照 workbook 中已有大小写。

## 卡点分析

- 文本规范误判：按自然语言大小写写入 title case，而评测按 workbook/golden 严格比较大写。
- 验证不足：只验证单元格模型和值存在，未检查与表头文本一致。
- 无命令误用、重试或环境问题。

## 归因分析

归因分类：agent 自身验证问题；数据/题目歧义/标注问题。

题目自然语言写 `Chep/Loscam`，但表头和 golden 为大写，存在轻微歧义。评测口径是严格值比较，因此 agent 应优先复用 workbook 表头。

## 建议

- 对分类标签来自列标题的题，输出应引用/复制表头原文本，避免自行规范大小写。
- 验证时用 `repr` 或 raw value 检查大小写、空格等不可见差异。
