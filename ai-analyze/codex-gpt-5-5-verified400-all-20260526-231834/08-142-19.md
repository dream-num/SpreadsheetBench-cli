# 08-142-19

## 结论

评测失败是 agent 对分块排序中的重复 header 行处理错误。golden 保留每个非空块的 header 行，例如 row 16 仍为 `Number/Name`；agent 从 row 16 开始把 header 当作普通数据参与排序，导致第二块整体上移，`A1:B82` 有 78 个值差异。

归因：agent 自身题意理解/验证问题。

## 证据与复现

- answer_position：`'Sheet1'!A1:B82`
- output：`.runs/univer-agent/codex-gpt-5-5-verified400-all-20260526-231834/142-19/task/outputs/case_1/output.xlsx`
- eval：`test_case_results: [0]`

关键对比：

- golden `A16:B16 = Number / Name`
- output `A16:B16 = A 37 / Best`
- golden `A17:B17 = A 37 / Best`
- output `A17:B17 = A 37 / Best1`
- output 把 `Number/Name` 排到了后面，golden 则把它作为块 header 固定保留。

范围外值差异为 0。

## 解题过程分析

agent 读取 `Sheet1!A1:B82`，执行 `/task/work/sort_blocks.js`。脚本从 `r = 1` 开始扫描，按空白行切分非空 block，然后对每个 block 的所有行按 A 列排序。

该逻辑只跳过了全表第一行 header，没有识别后续 block 的 header 行。

## 卡点分析

- 题面提到“500 total rows, blank rows interspersed”，并给了含 header 的范围；agent 没有处理每个 block 可能自带 header。
- 验证脚本 `/task/work/verify_sort.js` 只检查每个 block 是否升序，因此 header 被移走后仍可能被误判为“排序正确”。
- 无命令误用；导出成功；耗时 112 秒。

## 建议

分块排序应先识别 block 内 header，排序仅应用到 header 之后的数据行。验证不应只看“排序是否升序”，还应检查 header 坐标和空白分隔行是否保持。
