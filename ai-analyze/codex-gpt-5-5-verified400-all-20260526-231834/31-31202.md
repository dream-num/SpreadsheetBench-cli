# 31-31202

## 结论

该题失败是债务累计方向写反。`answer_position` 是 `J2:J47`，正式评测发现 `J35` 和 `J45` 两个值与 golden 相反：output 为负数，golden 为正数。

golden 公式是累计 `DEDUCTIONS(H)` 减累计 `ADDITIONS(G)`：`SUMIFS(H...)-SUMIFS(G...)`。agent 写成“上一周 debt + G - H”，即加 additions、减 deductions，导致有新增扣款/加款的行符号错误。

## 解题过程分析

agent 写了 `update_debt.js`，遍历 `J2:J47`。首行公式为 `=G2-H2`，后续用 `LOOKUP` 找同一 worker 的上一条 debt，再加 `G` 减 `H`。脚本等待公式计算，检查 `J2/J24/J47` 有公式并导出。

它没有检查包含非零 `ADDITIONS` 或 `DEDUCTIONS` 的关键行。实际错行是 `J35` 和 `J45`：这两行分别涉及 `H35=1500`、`G45=500` 等会暴露符号方向的值。

## 卡点分析

- 关键业务方向判断错误：把 additions/deductions 对 debt 的影响方向反了。
- 验证样本选择不足：抽样行没有覆盖非零变动行，导致公式形态看似正确但业务符号错误。
- 公式策略本身可行，范围没有越界，导出正常。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。

## 建议

涉及累计余额、债务、借贷方向的题，应先用至少一行非零 deduction 和一行非零 addition 手算验证。验证点不要只选首尾或显示为 0 的行。
