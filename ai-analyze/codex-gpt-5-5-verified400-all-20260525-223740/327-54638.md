## 输出差异

`openpyxl` 对比 `Sheet1!B2:B150`，共 149 个单元格，149 个全部不同：

- output 和 golden 都是数组公式，但公式文本不同。
- `B2` output: `=IFERROR(INDEX($A$2:$A$150,MATCH(0,INDEX(COUNTIF($B$1:B1,$A$2:$A$150)+($A$2:$A$150=""),0),0)),"")`
- `B2` golden: `=IFERROR(INDEX($A$1:$A$150,MATCH(0,INDEX(COUNTIF($B$1:B1,$A$1:$A$150),0,0),0)),"")`
- output 额外排除了空值并从 `A2:A150` 开始；golden 从 `A1:A150` 开始且 `INDEX` 参数形态不同。
- 149 个单元格都有字体差异。output/golden 工作表维度均为 `A1:B151`。

## 卡点分析

主要卡点是 agent 在样式/API 上反复探测并重跑，耗尽 300 秒预算。公式本身也未与 golden 对齐：题目文字提到 `A2:A150`，但 golden 公式使用 `A1:A150`；agent按题意写了一个合理但不匹配评测的版本。

存在明显耗时异常和失败重试。没有排序/截断风险，但有过度验证和反复导出风险。

## 归因分析

- agent 自身: 主要原因。超时由反复探测/重试导致；公式未按 golden 期望生成。
- univer-cli skill/API 文档不清: 次要。格式/样式 API 探测成本高，agent 在不熟悉 API 时消耗过多时间。
- univer-cli bug: 未见明确证据。
- 环境: runner 300 秒限制是直接失败条件之一，但不是根因。
- 数据/题目/评测: 有一定不一致风险；题面说 `A2:A150`，golden 公式使用 `A1:A150`。

## 改进建议

对这类公式题优先完成目标公式，样式只做最小必要复制；设置内部时间预算，避免在样式 API 上循环重试。若题面范围和已有公式/评测风格冲突，应检查输入中相邻示例公式，再决定是否包含表头。
