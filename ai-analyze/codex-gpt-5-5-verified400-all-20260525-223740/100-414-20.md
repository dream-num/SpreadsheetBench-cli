## 任务理解

题目要求在 A 列查找第一次出现的 `Invoice No.`，删除其上方所有行，保留 `Invoice No.` 行和下方内容。answer_position 给的是 `Sheet1!A4:A18`，但“删除整行”会导致行号上移，最终 golden 中 `Invoice No.` 出现在 `A1`。

## agent 解题过程

agent 在 `A4:A18` 搜索 `Invoice No.`，找到后调用 `sheet.deleteRows(firstAllowedRow, rowsToDelete)`。脚本把 `firstAllowedRow` 设为 `3`，这是 0-based 的第 4 行，然后验证 `A4` 是否为 `Invoice No.`。

过程没有明显 CLI 错误，主要问题是对“删除 rows above”后的目标位置理解错误：agent 以为保留在 `A4` 是正确结果，而 golden 要求删除整张表顶部行后让目标行移动到 `A1`。

## 输出差异

openpyxl 对比：

- output sheet 维度是 `A4:A4`，golden 是 `A1:A1`。
- output 的 `A4` 是 `Invoice No.`；golden 的 `A4` 为空。
- 在 answer_position `A4:A18` 内有 1 个值差异：`A4` output 非空，golden 为空。
- 这不是内容文本错误，而是删除行的起始边界错误导致的结构位置错误。

## 卡点分析

- 命令误用: `deleteRows` 参数本身可执行，但起始行选择错误。
- 失败重试: 未见重试。
- API 探测: 未见额外 API 探测，直接使用 `deleteRows`。
- 硬编码范围: 硬编码 `A4:A18` 和 `firstAllowedRow=3`；`A4:A18` 来自 answer_position，但删除上方行不应把 A1:A3 排除在删除范围外。
- 排序/截断风险: 无排序风险；主要是行位移边界。
- 验证不足: 验证条件写成 `A4` 等于 `Invoice No.`，刚好固化了错误预期。
- 耗时异常: 74s，正常。

## 归因分析

主要归因于 agent 自身对 Sheet-Level 删除行边界的理解错误。prompt 中 `answer_position` 是最大修改范围，但本题的宏语义需要删除 `Invoice No.` 上方的整行并使其上移；agent 过度约束在 `A4` 之后操作。未见 univer-cli bug 或环境问题。

## 改进建议

- 对删除整行/整列任务，验证应检查最终结构位置，而不是只检查原 answer_position 顶端。
- prompt/skill 可强调：Sheet-Level 的 answer_position 是评测范围，不代表所有结构操作都必须保持原始行号不变。
- 自检应同时查看 sheet `calculate_dimension()` 与目标文本最终坐标。
