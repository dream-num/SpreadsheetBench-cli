## 任务理解

题目要求对 `Sheet1` 中由空白行分隔的多个非空 `A:B` 区块分别排序，按 `A` 列 A-Z 排序，同时保持 `B` 列姓名和 `A` 列编号绑定，不跨空白区块排序。

## agent 解题过程

agent 先用 `pipe out` 读取 `A1:B82`，再写 `inspect_blocks.js` 和 `sort_blocks.js`。核心脚本识别空白行分隔的 block，保留表头行，然后用 `Intl.Collator("en", { numeric: true, sensitivity: "base" })` 对每个 block 的 `A` 列 key 排序。

## 卡点分析

- 没有命令失败或超时。
- agent 使用了 numeric collator，因此 `"D 6" < "D 7" < "D 14"`；golden 期望普通字典序下 `"D 14" < "D 6" < "D 7"`。
- 题目写的是 A to Z，不是自然数字排序。agent 自行加入 `{ numeric: true }` 导致排序规则偏离。
- 验证脚本也使用同一 collator 逻辑判断 `allSorted`，没有独立验证 Excel A-Z 排序语义。

## 归因分析

归因分类: agent 自身题意理解/推理/验证问题。

`univer-cli` 执行正常。失败根因是排序比较器选择错误，把文本编号当作自然数排序。

## 改进建议

- Excel 文本 A-Z 排序应默认按字符串字典序，不要启用 numeric collation，除非题目明确要求自然数字排序。
- 排序验证应使用与 Excel 行为一致的规则，并抽查含数字文本的边界样例。
- 对 `D 14` 这类值，应先判断它是文本标签而非数值编号。
