## 任务理解

题目要求修正 `INDEX/MATCH` 双条件取值，在 `Sheet1!C2:C3` 根据 A 列职位和 B 列月份，从 `Data` 表中取对应薪资。题干写了“Present the output values as numbers”，但上下文是“using the corrected formula”。

## agent 解题过程

agent 读取 skill 后检查 `Sheet1!A1:C3`、workbook 和 `Data!B2:AY4`，还探测了 range API。脚本 `fill_case_1.js` 读取 `Sheet1!A2:B3`、`Data!B3:B4`、`Data!C2:AY2` 和 `Data!C3:AY4`，直接匹配出数值后写入 `{v: 35, t: 2}`、`{v: 37, t: 2}`，清除了原公式。

## 输出差异

openpyxl 可正常读取 output 和 golden。工作表结构一致，`Sheet1` 维度均为 3 行 3 列。

`C2:C3` 共 2 个单元格：

- cached value 均一致：`C2=35`，`C3=37`。
- 公式/值类型均不一致：output 是普通数值，golden 是 `INDEX(...MATCH...)` 公式。
- 2 个 style_id 不一致。

样例：

- `C2` output 为数值 `35`；golden 为公式 `=INDEX(Data!$C$3:$AY$4,MATCH(A2,Data!$B$3:$B$4,0),MATCH(B2,Data!$C$2:$AY$2,0))`，cached value 也是 `35`。

## 卡点分析

agent 把“Present the output values as numbers”理解为可以写死静态数值，忽略了题目要求“Using the corrected formula”。它没有验证公式是否仍存在，只验证了数值和类型。

## 归因分析

主要归因于 agent 自身题意理解偏差：结果值正确，但交付形态错误。没有 evidence 指向 CLI bug 或环境问题。

## 改进建议

- 当题干要求“corrected formula”时，即使要求展示为数字，也应保留公式并让公式计算出数值。
- 验证应同时检查 `cell.data_type == 'f'` 或 Univer cell model 的 `f` 字段。
- 不要用脚本直接查表写静态值替代公式，除非题目明确要求 values only。
