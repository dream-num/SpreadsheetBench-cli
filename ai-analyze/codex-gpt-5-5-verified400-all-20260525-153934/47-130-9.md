## 任务理解

题目要求把 `cdnr` 源表数据按相同 header 文本对齐后追加到目标 sheet `b2b, sez, de` 的第一个空行，从第 7 行开始，不覆盖已有行；`L:M` 金额要写成负数并保留目标 number format；每个插入行还要设置指定状态/类型列。

## agent 解题过程

agent 多次 inspect 目标、源表和 Expected 表，又探测格式 API。核心脚本读取 `cdnr!A5:V8`，按目标列构造 22 列输出，针对 `E` 列做特殊映射，`H` 清空，`I` 写 `Credit Note`，`L:M` 写负数。导出时先使用 `univer export ... --overwrite`，出现 `Unknown argument: overwrite`，之后查看 help，删除输出文件并用 `--json` 成功导出。

## 输出差异

openpyxl 对比 `A5:V10`，值基本一致，差异为 16 个格式差异：

- `N7:P7`、`N8:P8`、`N9:P9` 的值都是 `0`，但 output number format 为 `General`，golden 为会计/数字格式 `_ * #,##0_ ;_ * \-#,##0_ ;_ * "-"??_ ;_ @_ `。
- 第 9 行 `A:G` 等单元格值一致，但 output 显式写了 `left/right` 对齐，而 golden 对应 alignment 为默认空。
- `L:M` 负数值和主要字段值与 golden 一致。

## 卡点分析

- 有一次命令误用：`univer export --overwrite` 不支持，报 `Unknown argument: overwrite`，后续通过删除旧文件并 `--json` 导出恢复。
- agent 只重点保护了 `L:M` 的格式，没有完整保留目标行模板中 `N:P` 等金额/零值列的 number format。
- `negativeCell` 把负数写成字符串形式再标 `t: 2`，虽然导出值正确，但模型语义存在风险。
- 验证脚本比较 raw values 与 Expected，未检查 number format 和 alignment。

## 归因分析

归因分类: agent 自身验证不足和格式保留问题；另有 `univer-cli` 命令参数误用。

最终失败不是导出失败。主要原因是 agent 没有按题意“preserving destination’s number formats”推广到同类数值列，也没有用 openpyxl/样式级验证发现格式差异。

## 改进建议

- 追加整行时应以目标空白模板行的完整 cell model 为底，再覆盖值，避免只处理少数列。
- 格式敏感题必须验证 number format、alignment、style id，不只比较 raw values。
- 避免 `--overwrite` 这类未确认参数；使用 `univer help export` 后再调用。
