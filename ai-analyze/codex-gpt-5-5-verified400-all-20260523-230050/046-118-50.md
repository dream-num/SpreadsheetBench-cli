## 卡点分析

- agent 将候选规则实现为“生成的转换词存在即输出”，因此额外收录了 `TABORING/ABORTING`。
- 对 `ING` 组内排序理解错误：output 为 `DREADING, HEARTING, SHEARING, TABORING, TAVERING`，golden 为 `TAVERING, HEARTING, SHEARING, DREADING`。
- 题目只明确了组顺序，没有明确组内排序规则，agent 按自身推导验证，未发现与预期不一致。
- 清空未使用区域导致大量空白 cell model 与 golden 不同，但主要业务失败是前 12 行内容/顺序。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。agent 对词对筛选和组内排序规则的实现与 golden 不一致，并用自生成结果自证。
- 数据/题目歧义或其它问题：有一定因素。题面没有清楚规定每个 ending 组内部的排序和是否要排除 `TABORING/ABORTING` 这类看似符合变换的词对。
- univer-cli 命令或 API 问题：未见证据。读写导出均成功。

## 改进建议

- 对模式匹配题，验证不应只复跑同一算法；应抽样人工检查每个组的候选全集、被排除项和组内顺序依据。
- prompt 可补充：当题目给出组顺序但未给出组内排序时，保留源数据扫描顺序，除非明确要求字母排序。
- 对清空大范围输出，尽量保留空白 cell model 或至少确认评测是否严格比较空白类型，减少非业务 blank 差异。
