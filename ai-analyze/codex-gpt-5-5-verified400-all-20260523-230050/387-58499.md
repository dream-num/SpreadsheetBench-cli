## 题目概览

- run-id：`codex-gpt-5-5-verified400-all-20260523-230050`
- 任务类型：Cell-Level Manipulation
- 指令摘要：列出 A 列中在 I 列没有 tick mark 的 branch。
- answer_position：`A13:A14`
- 工作表：`Sheet1`

## 评测结论

评测失败。runner 状态为 `ok`，耗时约 87 秒；`.univer` 内验证显示 `A13:A14` 为 `BR2/BR4`，但导出的 `output.xlsx` 中 `A14` 丢失。

## 解题过程分析

agent 读取 skill、检查 `Sheet1!A1:I14` 后，创建 `/task/work/case_1_set_formula.js`。脚本清空 `A13:A14`，在 `A13` 写入动态数组公式 `=FILTER($A$2:$A$7,$I$2:$I$7="")`，等待计算后返回 `A13:A14` values。日志中 `univer pipe out Sheet1!A13:A14 --format json` 显示 `["BR2"],["BR4"]`，agent 据此导出。

关键问题发生在导出结果：dynamic array 的 spill 在 `.univer` 可见状态中存在，但没有正确落到 xlsx 的 `A14`。

## output vs golden 差异

使用 `openpyxl` 对比：

- `A13:A14` 两个目标单元格都与 golden 公式形态不同；`A14` 的缓存值也错误。
- output：
  - `A13 =FILTER($A$2:$A$7,$I$2:$I$7="")`，缓存 `BR2`
  - `A14` 为空，缓存为空
- golden：
  - `A13` 为数组公式：`=IFERROR(INDEX($A$1:$A$7,_xlfn.AGGREGATE(...,ROWS(A$13:A13))),"")`，缓存 `BR2`
  - `A14` 为对应数组公式，缓存 `BR4`
- output sheet 维度为 `A1:I13`，golden 为 `A1:I18`；golden 在 `A15:A18` 还有向下填充的空结果公式，但这部分超出 answer_position。
- output 相对 init 未产生 answer range 外污染。

## 卡点分析

agent 选择了现代动态数组 `FILTER`，并只在 `.univer` 内验证 spill 结果，没有在导出的 `output.xlsx` 中重新读取 `A13:A14`。日志证据显示 export 前 `univer pipe out` 能看到 `BR4`，而 `openpyxl` 读取 output xlsx 时 `A14` 为空，说明 `.univer` 可见计算结果与 xlsx 导出结果不一致。

## 归因分析

- univer-cli 命令或 API 问题：主要原因。具体证据：`univer pipe out` 在导出前显示 `A13:A14 = BR2/BR4`，但 `univer export` 后的 `output.xlsx` 中 `A14` 为空，dynamic array spill 没有被序列化/缓存到 xlsx。
- agent 自身题意理解/推理/验证问题：次要原因。agent 未按导出文件复核，且在兼容性敏感的评测环境中使用了 spill 公式而非逐格公式。
- skill 指引/API 文档不清：可作为次要改进点。skill 应提醒 dynamic array spill 在 export 后需要复核，必要时写逐格公式。

## 改进建议

- 公式会 spill 时，导出后必须读取 xlsx 的 answer_position，不能只信 `.univer` 内部显示。
- 为了评测稳定性，优先给 answer_position 每个单元格写显式 `INDEX/AGGREGATE` 公式，避免依赖 spill。
- 若继续使用 `FILTER`，需要确认 `univer export` 支持 dynamic array 的公式属性、缓存和 spill 范围。
