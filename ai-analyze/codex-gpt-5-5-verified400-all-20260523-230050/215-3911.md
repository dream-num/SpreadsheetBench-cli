## output vs golden 差异

`openpyxl` 可读取 golden/init，但读取 output 报错：

`TypeError: expected <class 'openpyxl.styles.fills.Fill'>`

使用只读 XLSX XML 对比 `H2:P8`：

- 所有 63 个目标单元格的数值与 golden 一致。
- 所有 63 个目标单元格的公式缺失；output 是静态数字，golden 是公式。

典型差异：

- `H2` output 值 `5`、无公式；golden 值 `5`、公式 `MIN(INT(E2/1000),D$13)`
- `J4` output 值 `4`、无公式；golden 值 `4`、公式 `MIN(INT((E4-H4*1000-I4*500)/200),D$15-SUM(J$2:J3))`
- `P8` output 值 `4`、无公式；golden 值 `4`、公式 `MIN(INT((E8-H8*1000-I8*500-J8*200-K8*100-L8*50-M8*20-N8*10-O8*5)/1),D$21-SUM(P$2:P7))`

目标区域外业务数据未被刻意修改，但 output XML 中若干文本出现换行包装；同时 output 样式表导致 `openpyxl` 无法读取。

## 卡点分析

- agent 解决了数值分配，但没有保留/生成公式。
- 验证只覆盖 row total、column total、总张数，未检查 formula model。
- 使用了不存在的 `--overwrite` 参数，随后用 `rm -f` 重试；最终导出成功，但暴露 CLI 语法掌握问题。
- output xlsx 存在 `openpyxl` 样式读取失败，属于导出兼容性问题。

## 归因分析

- agent 自身公式处理/验证问题：主因，目标数值全对但公式全缺失。
- univer-cli 命令或 API 问题：output xlsx 样式表无法被 `openpyxl` 读取，证据是 output 报 `Fill` 类型错误，而 golden/init 正常。
- agent 命令误用：`univer export --overwrite` 是未知参数，日志中有明确报错。

## 改进建议

- 对分配表这类 Excel 解法题，优先写公式，不能只写最终静态值。
- 验证时检查 `getFormulas()` 或 XLSX 公式节点，而不只检查合计。
- export 前用 `univer help export` 确认支持参数；不要猜测 `--overwrite`。
- 将 `openpyxl` 读取 output 样式失败归档为通用导出兼容性问题。
