# 245-32023

## 题目概览

- run-id：`codex-gpt-5-5-verified400-all-20260523-230050`
- 题目号：`32023`
- 类型：Cell-Level Manipulation
- answer_position：`B2:B17`
- 任务要求：根据工作簿中的日期，给员工当前部门列生成公式，按达到对应日期后切换到相应部门代码。

## 评测结论

评测为失败。容器正常退出，`docker.timing.json` 显示 `returncode=0`、未超时、耗时约 117 秒。主要值差异集中在 `B2:B3`：output 写出了 `C78`，golden 为空。

## 解题过程分析

agent 读取 `A1:L20` 和 `B2:B17`，然后运行 `/task/work/set_case_1_formulas.js`。脚本对 `B2:B17` 全范围都写公式，并使用：

```js
const sourceRow = targetRow + 2;
```

例如 `B2` 使用第 4 行数据，`B3` 使用第 5 行数据。stdout 称已验证公式和可见结果，但验证没有发现 `B2:B3` 在 golden 中应为空。

## output vs golden 差异

用 `openpyxl` 对比：

- `B2:B17` 共 16 个单元格。
- 缓存值差异 2 个：
  - `B2`：output `C78`，golden 空
  - `B3`：output `C78`，golden 空
- 公式差异 16 个：output 全部是嵌套 `IF`；golden 的 `B4:B17` 使用 `=_xlfn.XLOOKUP($C$3,D4:L4,$D$1:$L$1,"",-1)` 形式，`B2:B3` 为空。
- 样式、数字格式无差异。
- sheet 结构一致，未发现 answer 区域外污染。

## 卡点分析

- answer_position 包含 `B2:B17`，但实际员工数据从第 4 行开始；agent 没有识别 `B2:B3` 是表头/空白占位区域。
- `sourceRow = targetRow + 2` 的映射让 `B2` 对应 `Smith, John 1`，造成前两行多写结果。
- agent 验证时只确认自己写入的公式和结果存在，没有检查应保持空白的上方区域。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。范围边界和行映射判断错误，未区分 answer_position 内的空白/表头行与实际数据行。
- prompt/runner/评测流程问题：轻微相关。answer_position 给出 `B2:B17`，但 golden 实际只从 `B4` 开始有结果，容易诱导 agent 对全范围写入；不过 prompt 也要求只完成请求效果，仍应由 agent 检查表结构。

## 改进建议

- 对 answer_position 内包含空白/标题区域的任务，先根据相邻列内容定位真实数据行，不应机械填满整个范围。
- 验证时应包括“应为空的单元格仍为空”，尤其是目标范围顶部和底部。
- prompt 可补充：answer_position 是最大允许范围，不代表每个单元格都必须写入。
