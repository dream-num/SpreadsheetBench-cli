## 卡点分析

- 题意边界卡点：agent 只关注前三年示例，未处理后续年份 deposit 为空时应“保持累计财富不变”的需求。
- 公式设计卡点：`IF(Bn="","",...)` 把空 deposit 行清空，而 golden 用 `Bn` 空值参与加法，效果是沿用上一累计。
- 验证不足：agent 只验证 `H2:H4`，没有检查 `H5:H40` 全 answer_position，尤其是空白行后的延续结果。
- 格式遗漏：没有复制/设置 `H` 列货币格式，导致 39 个目标单元格格式均与 golden 不符。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要归因。边界行处理错误且验证范围过窄。
- skill 指引/API 文档不清：次要。已有提示要求验证 answer_position 和格式敏感值，但 agent 没有充分执行；不是文档直接缺陷。
- 不归因于 `univer-cli` 命令或 API 问题：写入、计算、导出均成功；错误来自公式逻辑和格式选择。

## 改进建议

- 对整段公式填充题，验证必须覆盖目标范围的首行、示例行、第一条空输入行和尾行，不能只看题干示例。
- 累计/递推公式遇到空输入时，应先判断题目是否要求停止、留空或沿用上一累计；本题应沿用上一累计。
- 写目标列公式时继承相邻/源列数值格式，尤其是金额列应保留货币格式。
- 通用 prompt 可强调：当 answer_position 比非空源数据更长时，要检查空白输入区的 golden-like 预期行为。
