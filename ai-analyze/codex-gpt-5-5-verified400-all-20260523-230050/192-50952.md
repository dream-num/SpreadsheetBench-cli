## 评测结论

评测失败。runner 执行成功，`docker.timing.json` 显示 returncode=0、未超时，耗时 65.898s；但 `outputs/eval_univer_agent_gpt-5.5_codex-gpt-5-5-verified400-all-20260523-230050.json` 中该题 `test_case_results` 为 `[0]`。

## 解题过程分析

agent 加载了 `univer-cli` skill，检查了 workbook，并用 `univer pipe out` 读取 `Munka1!A1:G5`。随后它写了一个静态结果矩阵到 `G2:G5`：

`[[""],["4rd60pvdfyyy"],[""],["4piral6038fe"]]`

这里有两个关键问题：

- agent 只读取到 `A1:G5`，但 golden 公式使用的数据表范围是 `A2:B7`，即实际匹配候选包含第 6、7 行。
- agent 把结果写成静态值/空白，而 golden 在 `G2:G5` 使用逐行数组公式。

日志中还出现一次模型列表刷新超时：`failed to refresh available models: timeout waiting for child process to exit`，但主任务没有因此失败。

## output vs golden 差异

使用 `openpyxl 3.1.5` 可正常读取 output、golden、init。目标区域差异如下：

| 单元格 | output | golden |
| --- | --- | --- |
| `G2` | 空 | 公式 `LOOKUP(2,1/SEARCH(E2,$B$2:$B$7)/SEARCH(F2,$B$2:$B$7),$A$2:$A$7)`，缓存值 `4l8yyteflony` |
| `G3` | 静态值 `4rd60pvdfyyy` | 同类数组公式，缓存值 `4rd60pvdfyyy` |

值层面 `G2`、`G4` 缺失；公式层面 `G2:G5` 全部缺失。`openpyxl` 对比 output 与 init 未发现 `answer_position` 外的可见值污染；sheet 结构均为单表 `Munka1`。

## 卡点分析

- 读取范围不足：只看 `A1:G5`，没有覆盖 golden 公式依赖的 `A2:B7`，导致漏掉 `G2`、`G4` 的匹配。
- 匹配规则过度保守：agent 自述按“token-like text despite separators”查找，未按题意处理“参数可出现在任意位置、分隔符不固定”的泛化包含匹配。
- 验证不足：只验证了写入后的 `G2:G5`，没有用全表候选重新计算或与公式语义对照。
- 公式保留不足：题目问“Excel 如何实现”，golden 期望公式；agent 写静态值。

## 归因分析

- agent 自身题意理解/推理/验证问题：主因。agent 缩小了候选范围，并将“任意位置包含”理解成只在已读样本内查找。
- agent 自身公式处理问题：写入静态值而不是目标公式，导致公式类型不匹配。
- 环境/模型/超时问题：有模型列表刷新超时日志，但命令最终成功，不是本题失败主因。

## 改进建议

- 对查找类任务先确认实际 used range，不要只依赖 prompt 样例或前几行。
- 如果 instruction 是“如何用 Excel 公式”，优先写公式，并验证公式文本、缓存值和目标值。
- 匹配文本时使用题意的包含逻辑，并用每个目标参数回溯输出匹配来源行，避免只看写入结果。
