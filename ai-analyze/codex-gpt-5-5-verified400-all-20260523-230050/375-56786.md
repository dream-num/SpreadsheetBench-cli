## 解题过程分析

agent 读取 skill 后检查 `Sheet1!A1:C80`、`A20:C105` 等区域，查看 run API 帮助，然后用 `/task/work/write_rolling_average.js` 写入 `C4:C200`。它将 `C4` 留空，从 `C5` 开始写 `AVERAGEIFS($B$4:$B{row-1}, ... "<="&A{row})`，也就是只平均当前行之前的历史记录。导出前验证了 `C70/C80/C99` 等样例值。

关键偏差：golden 的公式包含当前行，并使用 Table structured reference；agent 使用普通 A/B 列范围且排除了当前行，导致每一行滚动窗口都错位。

## output vs golden 差异

- `C4:C200` 共 197 个目标单元格全部不同。

  - 后续行均为相同 Table 公式结构，包含当前行。

- output 与 init 在 answer range 外没有值/公式污染；output 维度沿用 init 的 `A3:D515`，golden 维度为 `A3:I200`，差异来自 golden 的 Table/结构化输出。

## 卡点分析

agent 写公式时把“previous 365 days”理解为“当前行之前的 365 天”，但 golden 期望包含当前日期这一行。它也没有实现题目偏好的 Table 结构，导致公式不具备 structured reference 和格式。验证样例是 agent 自己选择的值，没有与 workbook 中已有示例或最终 golden 语义进行独立对照。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。滚动窗口边界排除了当前行，且未实现 Table 公式。
- prompt/runner/评测流程问题：次要原因。“previous 365 days”是否包含当前行有一定自然语言歧义，但 golden 明确包含当前行。

## 改进建议

- 处理 rolling window 时明确窗口闭区间：`date >= current_date - 365` 且 `date <= current_date`，是否包含当前行要用样例核验。
- 若题目提到 Table 且 golden 可能使用结构化引用，应优先保留/创建 Table 或至少匹配其公式语义和格式。
- 验证不能只抽查自算样例，应把前几行边界点纳入验证；本题 `C4` 是否为空就是决定性信号。
