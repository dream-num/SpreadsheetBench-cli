## 总体归因

### Agent 自身问题为主

主要类型：

- 题意理解错误：例如正负号方向、lookup 方向、排序口径、是否包含当前行、月末 open 定义、控制值含义等。
- 范围/边界错误：漏读尾部数据、硬截范围、把 `answer_position` 当目标起点、行列错位、未处理局部表头。
- 公式与静态值口径不一致：大量题目 output 写静态值，golden 期望公式；或公式结构与 golden 明显不同。
- 验证不足：agent 常只看局部样本、只验公式存在、不验导出后的 xlsx、不验缓存值/格式/空白模型。
- 格式与类型不稳：日期/文本/百分比/空白/大小写/尾随空格/数字格式差异频繁出现。

代表题：

- `003-22-47`: 先截断后排序，漏保留数据。
- `029-469-9`: Debit/Credit 正负号映射反了。
- `048-142-19`: A-Z 文本排序误做自然数字排序。
- `049-146-49`: 词对集合正确但左右列方向反了。
- `213-3002`: 重复判定规则理解错。
- `329-54717`: 把控制值当 worksheet 行号。
- `359-43213`: 把输出列误当源数据列。

### `univer-cli` / export 问题集中在动态数组和样式

较明确的 CLI/export 风险：

- 动态数组 spill 在 `.univer` 中可见，但导出 `.xlsx` 后缓存或 spill 范围缺失。
- 导出的 `styles.xml` 出现非法空 `<fill/>`，导致 `openpyxl` 无法加载或评测失败。
- 有些公式/缓存值在 Univer 状态与 xlsx 导出后不一致。

代表题：

- `220-7665`: 动态数组只写入 `Q2`，导出后 `R2:V2` 为空。
- `323-54085`: `FILTER` 在 Univer 内正确，导出 XLSX 未保留 spill/cache。
- `340-56378`: 动态 `FILTER` spill 导出后未保留。
- `387-58499`: `.univer` 中 `FILTER` spill 正确，导出后 `A14` 丢失。
- `193-51090`, `207-54590`, `215-3911`, `258-35742`, `315-52541`, `332-55060`, `384-57989`: output xlsx 存在 `openpyxl` 样式读取失败或非法样式 XML 风险。

### Skill/API 文档不够清楚的方向

不是所有失败都能归因给文档，但以下方向会影响 agent 成功率：

- 需要更明确提示：最终评测看导出的 `.xlsx`，不能只相信 `.univer` 可见结果。
- 需要更明确提示：动态数组/`FILTER`/spill 结果必须导出后复核整个 `answer_position`。
- 需要更明确提示：不要随意用静态值替代公式，尤其题目要求修公式、查找、条件求和、动态计算时。
- 需要更明确提示：空白 cell、文本数字、百分比、日期、尾随空格、公式缓存、number format 都可能影响评测。
- 需要更明确提示：`answer_position` 是评测范围，不等于允许清空/重建的全部区域，也不等于任务输入范围。

这些更像 prompt/skill 指引不足叠加 agent 执行策略问题，而不是单一 CLI API bug。

### Runner/环境问题较少但存在

- `118-535-20`: runner 启动 Codex 时参数过长，agent 未启动且无 output。归因偏 runner/环境命令构造。
- `130-33722`: agent 接近正确，但卡在 `univer export`，300 秒超时无 output。归因含环境/超时与 export 性能风险。

### 数据/题目歧义

部分题目从自然语言看存在隐藏口径或 golden 口径不直观：

- `233-13284`: agent 按题面过滤 End 为空区间，golden 视为空开放区间。
- `246-32093`: 多候选新员工时 golden 期望 `ERROR`，题面未显式说明。
- `047-130-9`: 业务可见值基本正确，失败集中在空白 cell model/样式保真与导出链路归一化。

这类题仍可通过更强验证降低失败，但不能完全归为 agent 推理错误。

## 高频失败模式

### 公式 vs 静态值

许多 Cell-Level 题目输出值看起来接近，但 golden 保留公式。评测对公式、缓存或类型敏感时失败。

代表题：`115-524-31`, `180-49300`, `185-50193`, `215-3911`, `217-5835`, `318-53161`, `376-56915`, `399-59884`。

建议：

- prompt 中明确：题目要求修公式/自动计算时优先写公式，不要只写当前 case 的静态结果。
- agent 必须用 `openpyxl` 同时比对 `cell.value`、`cell.data_type`、`number_format`。

### 导出后验证不足

agent 经常在 `.univer` 或脚本中认为已正确，但没有重新读取最终 `output.xlsx` 验证。

代表题：`220-7665`, `323-54085`, `340-56378`, `387-58499`, `130-33722`。

建议：

- prompt/skill 加强“导出后必须检查 `output.xlsx` 的 answer_position”。
- 对动态数组题，要求检查 spill 目标区域每个 cell，而不是只检查公式起点。

### 范围边界与局部数据漏读

包括硬截范围、漏读后续行、没有处理空行分段、误把目标范围当输入范围。

代表题：`003-22-47`, `038-80-42`, `092-387-16`, `100-414-20`, `192-50952`, `200-52575`, `288-44628`, `377-56953`。

建议：

- prompt 要求先扫描 used range、表头和非空边界，再决定处理范围。
- 对排序/筛选/汇总题，必须输出处理前后行数和关键样本验证。

### 格式、类型和空白模型

包括百分比文本、日期误解析、空字符串 vs 0、尾随空格、大小写、空白 cell model、非法样式 XML。

代表题：`095-398-14`, `108-486-17`, `176-48983`, `177-49036`, `211-1925`, `309-51680`, `336-55965`, `372-55977`, `384-57989`。

建议：

- prompt 强制把格式和类型纳入最终验证。
- CLI/export 侧优先修复非法 styles XML 和空白 cell 保真问题。

## 优先改进建议

1. 修复或规避 `univer export` 非法 styles XML。
   影响多题，且会让 `openpyxl`/评测无法读取 output。

2. 针对动态数组 spill 做导出一致性修复。
   `FILTER`/spill 在 `.univer` 正确但 xlsx 缺缓存，是高价值通用问题。

3. 加强 agent prompt 的最终验证规则。
   明确要求用最终 `output.xlsx` 对 `answer_position` 检查值、公式、类型、格式、空白和行列边界。

4. 加强“公式不要静态化”的通用规则。
   对 Cell-Level 公式修复、查找、聚合、动态计算题尤其重要。

5. 修 runner 的 Codex 参数过长问题。
   `535-20` 未启动 agent，属于可通用修复的流程问题。

6. 为动态数组题提供推荐实现路径。
   如果 export 不可靠，短期可提示 agent 避免仅依赖 spill 缓存，必要时显式填充结果范围并保留可评测形态。
