# 258-35742

## 题目概览

- run-id：`codex-gpt-5-5-verified400-all-20260523-230050`
- 题目号：`35742`
- 类型：Cell-Level Manipulation
- answer_position：`O4:O7`
- 任务要求：在 horse show 表中汇总每行蓝色 Points 单元格到绿色 Section Total。

## 评测结论

评测为失败。容器正常退出，`docker.timing.json` 显示 `returncode=0`、未超时、耗时约 103 秒。目标区域的缓存值与 golden 一致，但公式不同；此外最终 `output.xlsx` 无法被 `openpyxl` 正常加载，报错为 `TypeError: expected <class 'openpyxl.styles.fills.Fill'>`。

## 解题过程分析

agent 读取 `SANDBOX !E4:O7` 后运行两个脚本：

- `/task/work/case_1_set_totals.js`
- `/task/work/case_1_verify_totals.js`

写入公式为：

```excel
=SUM(IFERROR(VALUE(F4),0),IFERROR(VALUE(H4),0),IFERROR(VALUE(J4),0),IFERROR(VALUE(L4),0),IFERROR(VALUE(N4),0))
```

stdout 显示 agent 验证出的计算值为 `17, 7, 9, 6`，并成功导出。

## output vs golden 差异

优先用 `openpyxl` 时，output 读取失败：

- output：`TypeError expected <class 'openpyxl.styles.fills.Fill'>`
- golden/init 可正常用 openpyxl 打开。

因此用只读 XML fallback 对比 `O4:O7`：

- 缓存值一致：`O4=17`、`O5=7`、`O6=9`、`O7=6`。
- 公式不同：
  - output：`SUM(IFERROR(VALUE(F4),0),IFERROR(VALUE(H4),0),...)`
  - golden：`SUM(E4:N4)`、`SUM(E5:N5)`、`SUM(E6:N6)`、`SUM(E7:N7)`
- 样式结构异常：output 的 `xl/styles.xml` 中存在空 `<fill />` 节点，例如 fill id 13、15、20；这是 openpyxl 加载失败的直接证据。
- sheet 结构在 XML 层面仍为 `SANDBOX `，目标值存在。

## 卡点分析

- agent 选择了更复杂的 `VALUE/IFERROR` 公式，数值上正确，但不等于 golden 的简单行内 `SUM(E:N)` 公式。
- 更严重的是导出的 xlsx 样式表不被 openpyxl 接受；这不是 agent 脚本直接写样式造成的，脚本只写公式。
- agent 没有在导出后重新用 xlsx 级工具验证文件可读性。

## 归因分析

- univer-cli 命令或 API 问题：主要原因之一。具体证据是 `univer export` 生成的 `output.xlsx` 中 `styles.xml` 含空 `<fill />`，导致 openpyxl 无法加载；golden/init 不存在该问题。
- agent 自身题意理解/推理/验证问题：同时存在。agent 没有在导出后验证 xlsx 可读性，也没有保持与 golden 等价的简单 `SUM(E:N)` 公式形态。
- prompt/runner/评测流程问题：若评测严格比较公式而非值，本题会因公式等价但文本不同失败；但 output 样式不可读是更基础的文件质量问题。

## 改进建议

- 对每个导出文件增加 openpyxl 级别 smoke test，至少确认 workbook 可加载、answer_position 可读取。
- 若发现 `univer export` 产生空 `<fill />`，应记录为通用 CLI/export bug，并构造最小复现。
- 对求和题优先使用最简区域公式，避免不必要的 VALUE/IFERROR 改写。
