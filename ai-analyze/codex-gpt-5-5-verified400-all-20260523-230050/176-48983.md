## 卡点分析

- 主要卡点是 agent 对空源单元格的语义判断错误：把“没有值”主动转成空白，而 Excel 直接索引空单元格在公式结果中评为 0。
- 验证不足：agent 验证“blank where no source value”符合自己的假设，但没有检查 Excel/评测对空源交叉点是否应为 0。
- 命令/API 卡点：一次 `Incorrect shape`，但已修复；不是最终错因。
- 无排序、截断、范围边界或文件访问违规风险；目标范围限定正确。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要归因。源空白值处理错误，公式多包 `IFERROR`。
- skill 指引/API 文档不清：次要。提示中已有“值类型/格式敏感要验证”，但没有特别提醒 `INDEX` 取空单元格会返回 0 的 Excel 行为。
- 不归因于 `univer-cli` 命令或 API 问题：公式写入、计算和导出均成功；差异来自 agent 公式设计。

## 改进建议

- 对“copy data across/down”类题，不要擅自把源空白变成空字符串；应保留 Excel 公式默认结果，除非题目明确要求空白。
- 验证时抽查至少一个源空白交叉点和一个非空交叉点，确认空值语义。
- 通用 prompt 可补充：`INDEX` 返回空源单元格时，Excel 公式缓存常为 0；不要用 `IFERROR(...,"")` 改变语义，除非明确要求隐藏错误。
- 在公式任务中，若 golden 可能评公式文本，应避免额外包裹不必要的错误处理函数。
