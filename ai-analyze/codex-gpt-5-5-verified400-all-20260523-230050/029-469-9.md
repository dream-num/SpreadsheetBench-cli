## 卡点分析

- 没有工具链错误、命令重试或超时。
- 主要卡点是题意/业务语义：agent 直接套用了“负数为 debit、正数为 credit”的假设。
- 题目给出的 sample 中第一批金额为正数，golden 将这些正数写入 `Debits`，但 agent 没有用样例校验方向。

- agent 自身题意理解/推理/验证问题：主要原因。agent 错误推断 debit/credit 与金额符号的映射。

- univer-cli 命令或 API 问题：未见证据。读写导出均成功。

## 改进建议

- 对 debit/credit 这类业务语义题，不要仅凭通用会计直觉判断；应从 sample/golden-like visible pattern 或题目上下文反推正负方向。
- 验证时抽查首个正数和首个负数的目标列，避免“列标题正确但分配方向相反”。
- 若题面语义可能歧义，agent 应在内部计划中列出假设并通过工作簿样例验证。
