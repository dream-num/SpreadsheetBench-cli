- answer_position：`B20:B339`
- 任务要求：把 Group A 的按月列式数据转换为 Group B 的按日期行式数据，排除 `-9999`/`M`，处理 `NA` 和空值，并覆盖到 `B20:B339`。

## 评测结论

评测为失败。容器正常退出，`docker.timing.json` 显示 `returncode=0`、未超时、耗时约 211 秒。目标区域有 73 个缓存值差异，主要是日期映射整体错位，以及 `NA` 处理与 golden 不一致。

## 解题过程分析

agent 先 inspect `A1:AF25`、`A20:B45` 和 workbook。中途尝试读取 `A19:B339` 时出现：

```text
Range is out of bounds. Max rows: 262, Max columns: 33, Given range ... endRow:338
```

随后脚本 `/task/work/fill_case_1.js` 使用 `insertRows` 扩展工作表，并写入 `B20:B339`。脚本中的关键注释是：

```js
// Row 19 is 1951-1-1 in the workbook; B20 therefore aligns to 1951-1-2.
```

这导致 output 从 `B20` 开始按 1951-01-02 写值；golden 则将 `B20` 对应 1951-01-01。

## 卡点分析

- agent 根据 init 的 `A19=1951-01-01`、`A20=1951-01-02` 做映射，认为 `B20` 应从 1 月 2 日开始；golden 实际把 `B20` 作为 1 月 1 日数据起点。
- prompt 提到“First add row for April in Group A”和 Group B 到 `A20:A339` 的格式，暗示输出结构会重排日期行；agent 没有完整复现 golden 的日期对齐。
- 对 `NA` 的处理也有歧义：题面前半说 leaving NA values as blanks，Note 又说 “NA: mean No Data and I want to leave as NA in group B”。golden 选择保留 `NA` 字符串，agent 选择空白。
- 出现过范围越界后，agent 虽然扩展了行数，但没有验证关键日期点的 row/date/value 对齐。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。日期起点错位，且未验证 `A` 列日期与 `B` 列数据的对应关系。
- 数据/题目歧义或其它问题：次要原因。`NA` 应为空还是字符串 `NA` 的描述互相矛盾，但 golden 明确保留 `NA`。
- prompt/runner/评测流程问题：轻微相关。answer_position 只给 `B20:B339`，但题意涉及 Group B 日期结构，golden 还改变了日期行结构；这使只改 B 列的 agent 更容易错位。

## 改进建议

- 对列转行的日期任务，验证必须包含 row/date/value 三元组，而不是只看目标列代表性值。
- 对 `NA`、空白、0、无效数据，应从题中 Note 和现有 Group B 示例推断最终展示形式，并抽查对应日期。
- 发生 out-of-bounds 后，扩展行数只是第一步，必须重新 inspect 末端和关键边界行确认结构。
