## 卡点分析

- 公式边界风险：agent 用 `DATEDIF(date_header+1, maturity_month_end+1, "m")` 近似月份差，遇到 `2022-08-31` 到 `2023-02-28` 这类月末/非月末到期组合时，把不应付息的月判为付息。
- 验证不足：agent 只验证“代表性”单元格，没有覆盖月末日期与非月末 maturity 的组合。
- 过程上无命令失败，但有较多 API/help 探测；耗时 160s，正常但偏长。
- answer_position 不包含第 5 行，agent 正确没有修改 row 5。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。公式设计没有严格复刻以 maturity date 反推付款日的边界逻辑。
- skill 指引/API 文档不清：轻微相关。日志显示 agent 需要多次查看 run/formula/formatting 帮助，但最终错误不是 API 不清，而是财务日期公式推理不足。
- 未发现 `univer-cli` 命令或 API 直接导致目标区值错误的证据。

## 改进建议

- 对现金流/日期频率题，必须增加边界验证：月末 header、非月末 maturity、年/半年/季度频率、maturity 当月本金加息、临近但非付款月。
- 如果工作簿下方已有公式示例，应优先抽取公式语义并移植，而不是重新发明日期差算法。
- 公式区域大时不要只验证第一行，应抽样覆盖不同频率和不同 maturity 日期类型。
