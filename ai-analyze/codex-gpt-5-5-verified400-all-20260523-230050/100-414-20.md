# 100 414-20

## 题目概览

- run-id: `codex-gpt-5-5-verified400-all-20260523-230050`
- task: `414-20`
- 指令类型: Sheet-Level Manipulation
- answer_position: `'Sheet1'!A4:A18`
- 任务要求: 在 A 列大小写不敏感搜索第一次出现的 `Invoice No.`，删除其上方所有行，保留 `Invoice No.` 行及以下内容。

## 评测结论

评测失败。runner 状态 `ok`，耗时 82.178 秒，returncode 0，未超时。最终 workbook 基本没有完成预期行删除。

## 解题过程分析

agent 先用 `univer search` 在 `Sheet1!A4:A18` 搜索 `Invoice No.`，又 `inspect range` 查看 `A1:A25`，随后执行 `work/delete_rows_above_invoice.js`。脚本固定读取 `A4:A18`，发现 `Invoice No.` 位于该搜索范围第一个单元格，于是 `foundOffset = 0`，删除行数为 0。

脚本返回 `expectedInvoiceCellAfter: "Sheet1!A4"`，说明 agent 把 answer_position 的起点 A4 当成删除后的目标位置，而不是把第一次 `Invoice No.` 上方所有行删除后使其上移到 A1。

## output vs golden 差异

用 `openpyxl` 对比 `Sheet1!A4:A18`：

- answer 范围 15/15 个单元格存在值或样式差异。
- `A4`: output 仍为 `Invoice No.`，golden 为 blank。
- `A5:A18`: 可见值均为空，但样式与 golden 不同。
- answer 范围外有直接相关差异: golden 的 `A1` 为 `Invoice No.`，output 的 `A1` 为空。这说明 golden 期望删除 A1:A3 后整体上移，而 output 没有删除。
- sheet 结构 output/golden 都是 `Sheet1 18x1`，init 是 `14x1`；维度一致不代表内容正确。

## 卡点分析

agent 的卡点是把 `answer_position` 误用为搜索和目标定位范围。题目要求“删除第一次出现文本上方所有行”，搜索范围应是整列 A 的已用区；即使 answer_position 从 A4 开始，也不能据此认为 `Invoice No.` 删除后应留在 A4。agent 验证只搜索到了 A4 仍有 `Invoice No.`，反而把错误状态当成正确。

## 归因分析

- agent 自身题意理解/验证问题: 搜索/删除边界错误，未理解行删除会让 `Invoice No.` 上移。
- prompt/runner/评测流程问题: `answer_position` 为 `A4:A18`，但 golden 把关键结果放到 A1，容易和“只能修改 answer_position”规则冲突。
- 未发现 `univer-cli` 命令/API bug；脚本按 agent 逻辑成功执行。

## 改进建议

- 行删除任务应以整列/used range 定位第一次匹配项，再计算要删除的行数。
- 验证应检查删除后的首行是否为 `Invoice No.`，而不是只检查原 A4。
- 对会改变行号的操作，报告和脚本返回值应包含 `foundBefore`、`deletedRows`、`expectedAfterCell`，且 expectedAfterCell 应依据删除语义计算。
