## 卡点分析

- 关键卡点是启动命令参数过长：`Argument list too long`。
- 该错误发生在 `/usr/local/bin/spreadsheetbench-agent-task` 调用 `/usr/local/bin/codex` 时，早于任何 workbook 操作。
- 题目首行有超过千列，prompt 中嵌入了大量 header 内容，极可能导致 agent 启动参数超过系统 argv 限制。
- 没有命令误用、失败重试、API 探测、硬编码范围、排序/截断风险或验证不足，因为 agent 未启动。

## 归因分析

- prompt/runner/评测流程问题：runner 将过长 prompt 作为命令参数传给 `/usr/local/bin/codex`，触发 OS 参数长度限制。
- 环境/模型/超时问题：具体表现为容器内命令启动失败，returncode 126；不是模型推理错误，也不是超时。
- 不归因于 agent 自身题意理解/推理/验证问题：agent 没有执行机会。
- 不归因于 `univer-cli` 命令或 API 问题：没有任何 `univer` 调用。

## 改进建议

- runner 调 Codex 时避免把完整 prompt 放进 argv，改用 stdin、临时文件或已支持的 prompt-file 机制。
- 对超宽工作表 prompt 做通用压缩：只保留与任务相关的 header 摘要、列数和匹配列统计，避免把 1000+ 列完整塞进启动参数。
- runner 应在启动失败时明确标记为 infrastructure failure，并保留 prompt 长度、argv 长度、命令构造方式等诊断信息。
- 对这类“删除含关键字列”任务，可在通用 prompt 中鼓励先用 workbook 可见 API/脚本读取首行并按 header 条件删除，而不是依赖 prompt 中完整首行。
