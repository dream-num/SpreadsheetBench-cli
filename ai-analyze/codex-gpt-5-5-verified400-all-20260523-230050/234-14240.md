# 234-14240

## 题目概览

- run-id：`codex-gpt-5-5-verified400-all-20260523-230050`
- 题目号：`14240`
- 类型：Cell-Level Manipulation
- answer_position：`U4:U75`
- 任务要求：修正 `SUMPRODUCT` 公式，根据 `R/S/T` 的三个条件从 `C4:M75` 汇总结果，并更新 U 列。

## 评测结论

评测为失败。容器正常退出，`docker.timing.json` 显示 `returncode=0`、未超时、耗时约 126 秒。最终 xlsx 中 `U4:U75` 的缓存值全部是 `#NAME?`，golden 为数值结果。

## 解题过程分析

agent 执行了 workbook inspect、公式读取、`univer help run/formulas`，然后运行 `/task/work/fix_case_1_formulas.js`。脚本对每一行写入：

```js
=SUMPRODUCT(($A$4:$A$75=$R4)*($B$4:$B$75=$S4)*($C$3:$M$3=$T4)*$C$4:$M$75)
```

脚本等待了 `univerAPI.getFormula().onCalculationResultApplied()`，但返回对象只包含 `firstFormula` 和 `lastFormula`，没有返回或检查 `U4:U75` 的计算值。后续日志也只验证了公式文本，未对比数值。

## output vs golden 差异

用 `openpyxl` 对比：

- `U4:U75` 共 72 个单元格。
- 缓存值差异 72 个：output 全部为 `#NAME?`；golden 为数值，例如 `U4=1882`、`U5=2532`、`U75=28564`。
- 公式差异 72 个：output 为普通 `SUMPRODUCT(...)` 公式；golden 为数组公式对象。
- 样式差异 72 个，主要是字体颜色/theme 编码差异；数字格式无差异。
- sheet 结构一致，未发现 answer 区域外污染。

## 卡点分析

- agent 只确认公式写入，没有确认计算结果不是错误值。
- `#NAME?` 在导出文件中已经固化为缓存值，说明 `univer run` 后公式计算没有得到可评测数值。
- 公式本身是 Excel 常见写法，但 Univer 运行时/导出缓存未能正确计算，agent 没有降级为兼容数组公式或静态结果校验。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。题目需要 U 列结果，agent 没有验证计算值，只验证公式文本。
- univer-cli 命令或 API 问题：可能相关。证据是 `univer run` 正常返回、公式文本写入成功，但导出 xlsx 的缓存值全部为 `#NAME?`，表明 Univer 公式引擎或导出缓存对该 `SUMPRODUCT`/数组计算没有给出有效结果。
- skill 指引/API 文档不清：次要相关。虽然 prompt 已要求公式任务验证 raw value/visible display，但实际 agent 仍只返回公式，说明该要求对“公式可写但缓存错误”的风险强调不足。

## 改进建议

- 对公式修复题，`run` 脚本应返回目标区域的公式和计算值，并检查是否有 `#NAME?/#VALUE!/#ERROR!`。
- 如果 Univer 不能可靠计算 `SUMPRODUCT`，应考虑写入 golden 兼容的数组公式结构，或在可接受时写入计算后的值并保留必要公式说明。
- 将“公式写入成功不等于计算成功”作为通用 prompt/skill 检查项。
