# 372 - 55977

## 题目概览

- run-id：`codex-gpt-5-5-verified400-all-20260523-230050`
- 任务类型：Cell-Level Manipulation
- 指令摘要：根据 A 列日期替换星期相关数据；Monday 应为 day 1，Sunday 为 day 7；C 列显示对应星期。
- answer_position：`C2:C16`
- 工作表：`WEEKDAY`

## 评测结论

评测失败。runner 状态为 `ok`，耗时约 92 秒；最终 output 在 `C2:C16` 与 golden 全部不一致。

## 解题过程分析

agent 检查 `WEEKDAY!A1:C16` 和公式后，创建 `/task/work/fix_weekday_case1.js`，仅在 `C2:C16` 写入 `=INDEX({"Monday","Tuesday",...},1,WEEKDAY(Ax,2))`。导出前它用 `inspect range`、`pipe out --type formula` 和 `pipe out` 验证 C 列显示完整英文星期名。

问题在于 golden 对 C 列期望的是缩写星期名公式 `=TEXT(Ax,"DDD")`，例如 `Mon/Tue/Sun`，不是完整 `Monday/Tuesday/Sunday`。此外题面提到 B:C 两列，但 answer_position 只允许 `C2:C16`，golden 中 B 列也存在 `=WEEKDAY(Ax,2)` 公式，agent 未改 B 列是遵守 answer_position 的结果。

## output vs golden 差异

使用 `openpyxl` 对比：

- `C2:C16` 共 15 个单元格全部公式和值不同。
- output 示例：
  - `C2 =INDEX({"Monday","Tuesday","Wednesday","Thursday","Friday","Saturday","Sunday"},1,WEEKDAY(A2,2))`，缓存 `Monday`
  - `C3` 缓存 `Tuesday`
  - `C4` 缓存 `Sunday`
- golden 示例：
  - `C2 =TEXT(A2,"DDD")`，缓存 `Mon`
  - `C3 =TEXT(A3,"DDD")`，缓存 `Tue`
  - `C4 =TEXT(A4,"DDD")`，缓存 `Sun`
- 数字格式均为 `ddd`，样式无实质差异。
- answer range 外 output 相对 init 未产生污染；output vs golden 在 B9:B16 等处有差异，是 golden 额外包含 B 列 `=WEEKDAY(Ax,2)` 公式，而 output 未改 B 列。

## 卡点分析

agent 的卡点是把“actual day of week”理解为完整英文星期名，并把题干中提到的 INDEX 方案当作目标方案。它没有注意到现有格式/期望可能是 `ddd` 缩写，也没有在导出后用 Excel 文件层面对比实际 expected display。

## 归因分析

- agent 自身题意理解/推理/验证问题：主要原因。C 列输出粒度不对，完整星期名不等于 golden 的缩写星期名。
- prompt/runner/评测流程问题：次要原因。题干要求替换 B:C，但 answer_position 只给 C 列，golden 又包含 B 列公式，存在范围描述不一致；不过本题评测失败的核心仍在 C 列。

## 改进建议

- 日期/星期任务应同时检查公式、缓存值和显示格式；`ddd` 格式通常暗示缩写显示。
- 当题面提到 B:C 但 answer_position 只有 C 时，应严格只改 C，但报告/验证中标注 B 列无法改动，避免误判。
- 对自然语言中的“day of week”不要默认完整名称，应从已有单元格格式或样例显示推断。
