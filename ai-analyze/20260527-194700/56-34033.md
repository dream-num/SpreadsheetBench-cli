## 题目要求

在 `ExcelForum help!K6:K10` 写公式，根据 `H` 的 Item、`I` 的 Parameter 和 `J` 的 Date recall，返回该 item 在前后相邻日期区间中的对应参数值。评测只比较 `K6:K10` 的 `data_only=True` 值。

矩阵备注：`wrong-report-matrix.univer` 的 `codex-gpt-5.5-verified400` sheet 中该行备注为空。

## 评测差异

最新正式 run `codex-gpt-5-5-verified400-all-20260526-231834`：runner `ok`，评测 `PASS`，`K6:K10` 差异数为 0。

该题在矩阵中的最后失败来自 `codex-gpt-5-5-verified400-all-20260525-223740`。历史 run 的 `output.xlsx` 与 golden 只有 1 个差异：

- `K10`: output `None`，golden `95`

历史 output 中 `K6:K9` 为 `26, 250, 5, 301`，但 `K10` 为空；golden 需要 `95`。

## agent 解题过程与卡点

历史 run 一开始写了较复杂的 `COUNTIFS/SUMIFS` 区间公式，用当前行日期落在 `A_n <= J < A_{n+1}` 的区间来取参数。它还手动处理最后一行边界，但条件只在 `B13=H10` 且 `A13<=J10` 时加回最后一行；对 `K10` 的例子 `H10=A`、`J10=2023-07-05`，正确应返回 A 组最后记录 `2023-03-01` 的 Parameter 3 = `95`，但 agent 的最后行补丁只看全表最后一行 C 组，导致 A 组末尾之后的日期无匹配。

最新 run 改用 `LOOKUP(2,1/(($B$3:$B$13=$Hrow)*($A$3:$A$13<=$Jrow)), ...)`，直接找同 item 中不晚于 recall date 的最后一条记录，再按参数 header 取 `C:E`，因此 `K10=95` 并通过。

## 归因分类

历史失败归因于 agent 公式边界逻辑错误：只处理全表最后一行，没有处理每个 Item 分组的最后有效日期。最新 run 已通过。
