## 题目要求

在 `Sheet1` 的 `G4:G6, G11:G13, G20:G22` 放入正确公式，用于在人员位置不匹配时比较参与者姓名和开始日期。评测只比较这些 answer_position 内 `openpyxl.load_workbook(..., data_only=True)` 的 `cell.value`。

## 评测差异

对比 output 与 golden：

- `G12`: output `True`，golden `False`
- `G13`: output `False`，golden `True`
- `G21`: output `True`，golden `False`

output 写入的公式形如：

`=IF(COUNTIFS($D$11:$D$13,A12,$E$11:$E$13,"<="&B12)>0,TRUE(),FALSE())`

这以左侧表 `A:B` 当前行作为主键，在右侧 `D:E` 中查找同名人员。golden 的结果则以右侧列表当前行作为主键：例如第 12 行右侧是 `Person 3 / 2022-07-01`，应匹配左侧 `Person 3 / 2021-07-01` 并判断左侧日期是否大于等于右侧日期，所以为 `False`。

## agent 解题过程与卡点

日志显示 agent 读取了 `univer-cli` skill，检查 `Sheet1!A1:G24`，第一次误用 `univer inspect range --show-formulas`，遇到 `Unknown argument: show-formulas` 后改用 workbook inspect 与 `univer run` 读取模型。随后写入 `COUNTIFS` 公式并验证每个区块均为 `TRUE, TRUE, FALSE`，再导出。

卡点是公式方向理解错误：agent 认为应判断“左表当前人员是否存在于右表且右表日期 <= 左表日期”，但目标结果是按右表当前行回查左表人员并比较日期。agent 的验证只验证了自设预期，未与题目示例第二块的人工 true/false 语义对齐。
