# 23 - task 32023

## 题目要求

在 `Sheet1` 中根据指定日期返回员工当前部门代码，目标范围为 `B2:B17`。员工数据实际从第 4 行开始，日期列和部门变更列位于 `D:K` 附近。

## 评测差异

优先 run：`.runs/univer-agent/codex-gpt-5-5-verified400-all-20260526-231834`。

按 openpyxl `data_only=True` 比较 `B2:B17`，共有 2 个值差异：

- `Sheet1!B2`: output `C78`，golden `None`
- `Sheet1!B3`: output `C78`，golden `None`

golden 从 `B4` 开始填员工结果；`B2:B3` 属于工资/日期说明区，应保持空白。agent 却从 `B2` 开始写公式，因此污染了前两行。

证据路径：
- prompt：`.runs/univer-agent/codex-gpt-5-5-verified400-all-20260526-231834/32023/task/prompt.md`
- output：`.runs/univer-agent/codex-gpt-5-5-verified400-all-20260526-231834/32023/task/outputs/case_1/output.xlsx`
- work script：`.runs/univer-agent/codex-gpt-5-5-verified400-all-20260526-231834/32023/task/work/case_1_write_formulas.js`
- golden：`data/spreadsheetbench_verified_400/spreadsheet/32023/golden.xlsx`

## agent 解题过程与卡点

agent 先 inspect `Sheet1!A1:L19`，能看到员工名从 `A4` 开始。写入脚本却循环 `i=0..15`，令 `targetRow=i+2`、`sourceRow=i+4`，也就是把第一个员工 row 4 的公式写到 `B2`，整体上移了 2 行。

agent 的验证样本也沿用了错误映射：`B2` 对应 `A4`，并把这视为成功，因此没有发现 target range 前两行应为空。另一个过程问题是导出后 `C3` 的 TODAY 类日期从 initial/golden 的 `2025-10-16` 变成了 `2026-05-26`，虽不在 answer_position 内，但说明导出/重算会污染范围外可见值。

## 归因分类

agent 自身范围/边界错误。它没有根据表头和员工数据起始行调整目标起点，硬按 `B2` 写入，导致 `B2:B3` 不应填却被填。

## 是否建议写矩阵备注

建议写矩阵备注：`员工数据从 row 4 开始，agent 将公式写到 B2:B17 并用 sourceRow=row+2，导致 B2/B3 说明区被填 C78；属范围边界/验证不足。`
