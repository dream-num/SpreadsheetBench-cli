## 题目要求

题目要求删除每行字符串中从 `FT` 开始的所有文本，并把 `FT` 前面的文本输出到 Column B。关键措辞是 keeping the preceding text intact，即保留 `FT` 之前的原始文本。

## 评测差异

正式评测只比较 `B1:B4` 的 `data_only=True` 值。用 run 内 output 对比 golden，4 个目标单元格全部失败，差异都是末尾空格:

| 单元格 | output 长度 | golden 长度 | 差异 |
| --- | ---: | ---: | --- |
| B1 | 50 | 51 | golden 末尾多 1 个空格 |

golden 公式是 `=LEFT(Ax,FIND("FT",Ax)-1)`，会保留 `FT` 前的空格。agent 输出的是静态文本值，并去掉了该尾随空格。

## agent 解题过程与卡点

agent 加载 skill 后检查 `A1:B4`，确认源数据在 `A1:A4`、目标为空的 `B1:B4`。它写入 `/task/work/case_1_truncate_ft.js`，核心逻辑为:

```javascript
const ftIndex = text.indexOf("FT");
const result = ftIndex >= 0 ? text.slice(0, ftIndex).trimEnd() : text;
return [{ v: result, t: 1 }];
```

随后 `case_1_verify.js` 只检查 `B1:B4` 的 `v/t/f`，确认是字符串、无公式，然后导出。运行 `78.005s`，`returncode=0`，未超时。

卡点是 `trimEnd()` 的过度规范化。题目要求保留 preceding text，正式答案按 Excel `LEFT(..., FIND("FT")-1)` 保留了 `FT` 前面的分隔空格。agent 验证时只看显示文本和类型，没有用 `repr`、长度、末尾字符检查尾随空格。

日志开头有 `failed to refresh available models` 和 wham apps 请求错误，但 agent 后续正常执行并成功导出，非直接根因。
