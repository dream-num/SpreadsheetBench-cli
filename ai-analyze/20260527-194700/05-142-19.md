# 142-19 错题调查

## 题目要求与 answer_position

- 选用 run：`codex-gpt-5-5-verified400-all-20260526-231834`
- 题目要求：自动识别 `Sheet1` 中由空白行分隔的非空范围，分别按 A 列 A-Z 排序，并保持 B 列姓名与 A 列编号配对。
- `answer_position`：`'Sheet1'!A1:B82`

## 评测差异摘要

按正式评测口径比较，`Sheet1!A1:B82` 共 164 个单元格，78 个值不同。第一段 `A1:B15` 与 golden 一致；从第二段开始错位。

关键差异：

- golden `A16:B16` 保留第二段表头 `Number/Name`。
- output `A16:B16` 为 `A 37/Best`，即把第二段表头参与排序后移走或丢失。
- 后续各段同类错位，原因都是重复表头未被视为每个 block 的 header。

## Agent 解题过程分析

agent 从 `A1:B82` 读入，跳过 `r=0` 的首行表头，然后只用“空白行”划分 block。它没有把后续重复出现的 `Number/Name` 当作各段表头处理，而是把这些表头行作为普通数据行参与 block 排序。由于 `Number` 在字母序中排到数据之后，第二段及以后相对 golden 发生错位。

stdout 中说“sorted each nonblank block”，但验证脚本同样只检查 block 内 A 列是否有序和固定空白行是否为空，没有检查每段开头是否应保留 `Number/Name`。

## 卡点分析

- 命令误用：未见直接失败的 CLI 命令误用。
- 失败重试/API 探测：使用 `sort_blocks.js` 和 `verify_sort.js`，没有异常退出。
- 硬编码范围：硬编码 `A1:B82`，符合 answer_position。
- 排序/截断风险：排序算法未区分 block header 与数据行，导致 header 位置错误。
- 验证不足：验证条件“block 内 A 列有序”会把错误输出判为成功，因为 header 被排序后仍不一定触发它关注的违例。
- 耗时异常：111.907 秒，未超时。
- 约束风险：只写 `A1:B82`，未见范围外污染。

## 归因分类

agent 自身范围/边界与 header 处理问题。它只保留全表第一行 header，没有保留每个非空分段自己的 header。
