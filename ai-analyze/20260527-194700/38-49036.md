## 题目要求

在 `Dashboard!B8` 解析 `B6` 与 `B5` 中混合文本的前导数字，计算比例，并显示带 `WIN RATE` 后缀的百分比。评测只比较 `Dashboard!B8` 的 `data_only=True` 值。

矩阵备注：对应行备注为空。

## 评测差异

正式 run `codex-gpt-5-5-verified400-all-20260526-231834`，runner `ok`，评测 `FAIL`。

差异：

- output `B8` data_only 值：`0.6666666666666666`
- golden `B8` data_only 值：`'66.67% WIN RATE'`

output 公式/格式：

`=VALUE(LEFT(B6,FIND(" ",B6)-1))/VALUE(LEFT(B5,FIND(" ",B5)-1))`

number format 为 `0% "WIN RATE"`，显示为 `67% WIN RATE`。

golden 公式：

`=TEXT(VALUE(LEFT(B6,FIND(" ",B6)-1))/VALUE(LEFT(B5,FIND(" ",B5)-1)),"0.00%")&" WIN RATE"`

因此 golden 存储/缓存的是文本值 `66.67% WIN RATE`。

## agent 解题过程与卡点

agent 读取 skill，检查 `Dashboard!A1:D12`，识别 `B5/B6` 是 `3 TRADES`、`2 GOOD TRADES` 这类文本。它明确选择“保持单元格为数值百分比，通过自定义数字格式显示 WIN RATE”，写入数值公式和格式后用 `getCellDatas()` 验证 `v=0.666...`、display 为 `67% WIN RATE`，再导出。

卡点是它按“不要改变数字格式/保持数字”方向优化了单元格模型，但正式评测只比较 `cell.value`，golden 期望文本拼接结果且保留两位小数。即使视觉显示接近，`data_only=True` 值类型和内容都不同。

## 归因分类

agent 输出模型与 golden/评测口径不一致；也有题目表述歧义，prompt 提到保持 number format，但 golden 实际采用 TEXT 拼接文本。按当前评测，应归为 agent 未对齐数据集期望。
