## Agent 解题过程分析

主全量 run 在 480 秒超时，日志显示 agent 已运行 edit 脚本并返回 success，但超时前没有完成导出，`task/outputs/case_1/output.xlsx` 不存在。

env37 补跑中，agent 从 `Main!A1:J11` 读取数据，按 A:G 分组，正确转置金额并写入公式总计。失败点在 header 构造：它硬编码了题干中列出的 singular allowance names：

- `Transport Allowance`
- `Other Allowance`
- `Social Allowance`

同时它还用 `normDesc()` 将源数据中的 `Allowances` 归一化为 `Allowance`。golden 则保留了源 H 列中的复数描述作为表头。

## 卡点分析

- 命令误用：env37 run 未见直接失败的 CLI 命令误用。
- 失败重试/API 探测：env37 run 有 inspect、edit、verify 和 export；主全量 run 因 480 秒超时未导出。
- 硬编码范围：env37 run 硬编码读取 `A1:J11`，写 `A1:M3`，符合本 case；allowanceHeaders 硬编码为 singular 是直接失败点。
- 排序/截断风险：员工只输出两行，与 golden 一致；无排序问题。
- 验证不足：验证检查金额映射和总计，没有比较表头与源描述/golden 的 exact text。
- 耗时异常：主全量 run 480.188 秒超时；env37 run 87.472 秒正常完成。
- 约束风险：输出只在 `Output Required!A1:M3`，未见范围外污染。

## 归因分类

数据/题目歧义与 agent 硬编码共同导致。题干列名写的是 singular，但源数据和 golden 对 `Transport/Other/Social Allowances` 使用复数；agent 选择题干 singular 并归一化源描述，导致正式评测失败。主全量 run 另有超时执行问题，但最新可复现值差异是表头文本。
