# 错题表未调查题目汇总报告

## 范围与方法

- 矩阵来源：`wrong-report-matrix.univer`
- Sheet：`codex-gpt-5.5-verified400`
- 筛选口径：第 3 行以后 `task_id` 非空且 `备注` 为空的历史失败 task。
- 本次分析数量：60 题，逐题报告位于 `ai-analyze/01-*.md` 到 `ai-analyze/60-*.md`。
- 分析口径：先按正式评测逻辑复现，即 `openpyxl.load_workbook(..., data_only=True)` 读取 output/golden，只比较 `answer_position` 内 `cell.value`。公式文本、样式、填充色、字体色默认不作为失败依据，除非它们导致导出缓存或 openpyxl 可见值异常。

## 总体归因

本批未调查错题以 agent 自身题意理解、范围识别、排序/映射推理和验证不足为主。比较值得优先修复的通用问题有三类：

1. 动态数组/公式缓存导出问题：`15387`、`56419`，表现为 Univer 内可见 spill 或公式结果，但导出后的 xlsx 在 openpyxl `data_only=True` 下缓存缺失。
2. 运行环境/runner 超时或网络中断：`1925`、`3002`、`54638`，以及部分历史 run 中的 `203-15`、`48975`、`48983`、`208-20`、`448-11`。
3. 数据/题目/评测歧义：`118-50`、`13284`、`398-14`，题干、`answer_position` 或 golden 口径存在不一致。

其余大多数为 agent 执行策略问题：只读取小范围、硬编码范围、误解列映射、误处理空值、文本保真不足、误用动态公式但未用评测口径验证。

## 优先建议

1. 优先建立动态数组/公式缓存导出的最小复现：从 `15387` 和 `56419` 开始，确认是 Univer 导出缓存未落盘、公式计算未触发，还是 agent 没有用 openpyxl 口径验证。
2. 在 agent prompt 或 skill 中强化“评测口径验证”：最终导出后必须用 openpyxl `data_only=True` 检查 `answer_position`，尤其是动态数组、公式、空值、文本尾随空格和日期格式。
3. 针对高频 agent 错误补通用提示：完整 used range 扫描、不要截断到示例范围、保留文本空格/大小写、区分空值/0/`#N/A`/文本 `"-"`、结构操作后重新解释 `answer_position`。
4. 对环境/runner 类单独跟踪：超时无 output 与值差异失败不要混记；若最新 rerun 已通过，矩阵备注应标明历史失败形态和通过 run。
5. 对数据/题目歧义题建立单独备注，不建议用 prompt 调优硬扛，否则容易引入特化行为。
